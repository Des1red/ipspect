# Changelog

**Version:** `v3.0.0`  
**Date:** 14 October 2026  

## Engine Selection and CLI

* Added independent execution flags for the three scanning engines:

  ```bash
  --icmp
  --arp
  --tcp
  ```

* Running IPSpect without engine flags enables all three engines. Supplying engine flags enables only the selected engines; combinations can be provided in any order.

* Established a fixed execution order independent of flag order:

  ```text
  ICMP Discovery
       ↓
  ARP Discovery
       ↓
  TCP SYN Scanning
       ↓
  Service Identification
       ↓
  Scan Results
  ```

  Only the applicable stages run. A TCP-only scan does not require ICMP or ARP discovery.

* Added dynamic stage numbering based on the actual enabled workflow. An ARP-only run displays `01 / 01`; a full run displays five stages.

* Added `-t` / `--target` to provide a target directly on the command line instead of using the interactive prompt:

  ```bash
  sudo ipspect -t 192.168.1.1
  sudo ipspect -t 192.168.1.0/24 --arp
  ```

* Added `--verbose` output for inspecting discovery and scan details.

* Kept `-p` for explicit TCP port selection, and retained the v1.0.3 behavior of accepting individual ports, lists, ranges, and mixed specifications. Without `-p`, TCP still scans all ports from `1` through `65535`.

* Supported single IPv4 addresses and IPv4 CIDR scopes, with the configured maximum scope of `/16`.

## Target Handling and Prioritization

* Added a deduplicated TCP target ordering informed by available discovery results:

  1. ICMP responders.
  2. ARP-only responders not already included.
  3. Remaining original targets.

* Preserved the v1.0.3 guarantee that **nonresponding hosts are not removed** from the TCP scan. ICMP and ARP discovery change priority, not the requested scan scope.

* Added explicit handling for single-target and multi-target scan modes, allowing large default scans to avoid retaining unnecessary per-port closed/filtered records.

* Kept explicit `-p` scans detailed: closed and filtered entries for selected ports can be retained and presented even in focused multi-target scans.

## ARP Discovery

* Added an independent ARP discovery engine under:

  ```text
  internal/portscan/arp/
  ```

* Implemented raw Ethernet ARP discovery on Linux using `AF_PACKET` sockets.

* Added eligible network-interface selection and grouping of directly connected IPv4 targets by interface.

* Implemented broadcast ARP request construction, transmission, and reply parsing/validation.

* ARP replies are checked against the expected local IP/MAC and outstanding targets, then recorded with:

  * target IPv4 address;
  * reported sender MAC address;
  * interface used for discovery.

* Added response deduplication and thread-safe tracking of outstanding and discovered devices.

* Added per-target reply deadlines, **two retransmissions** after an initial ARP request, and a transmission rate of up to **500 packets/second**.

* Late replies are accepted while the address remains pending; duplicate replies are not counted as multiple discovered hosts.

* Preserved compatibility with observed local-network replies whose Ethernet frame source MAC differs from the sender MAC inside the ARP payload. The ARP payload is still validated against the targeted local address.

* ARP discovery is limited to directly connected Layer 2 networks; it does not make ordinary routed networks ARP-discoverable.

## Device Identification and ARP Enrichment

* Added ARP device enrichment in:

  ```text
  internal/portscan/arp/enrich/
  ```

* Added offline MAC manufacturer identification using embedded IEEE registration data:

  * **MA-L:** 24-bit prefix assignments;
  * **MA-M:** 28-bit prefix assignments;
  * **MA-S:** 36-bit prefix assignments.

  More-specific assignments take priority when matching a MAC prefix.

* Added detection of locally administered MAC addresses, whose manufacturer often cannot be identified reliably from an OUI.

* Added reverse DNS (PTR) hostname lookup for discovered addresses.

* Added NetBIOS Node Status queries over UDP port `137` to identify compatible workstation or file-server names.

* Added NetBIOS packet construction, transaction-ID validation, DNS-style name parsing, and filtering of unsuitable name entries.

* Enriched ARP results now report the discovered address, MAC, vendor, PTR name, NetBIOS name, and local interface when available.

* Preserved the distinction between identifying evidence and verified identity: vendor assignments and network-provided names are not proof of the device's exact manufacturer, model, or owner.

## Shared Adaptive Timeout Manager

* Introduced a dedicated, reusable timeout package:

  ```text
  internal/network/timeout/
  ```

* Replaced the previous fixed ICMP/TCP deadlines with adaptive, protocol-specific estimates. ARP also uses the shared manager.

* Added a synchronized timeout manager with:

  ```go
  Duration(mode, scope)
  Observe(mode, scope, rtt)
  Backoff(mode, scope, retry)
  ```

* Estimates are based on smoothed RTT and RTT variation, with scope-level observations, mode-level fallback, minimum/maximum bounds, and **four valid samples** required before an estimate is used.

* Added capped exponential backoff for subsequent attempts.

* Prevented ambiguous RTT measurements following retransmissions from training the estimator, since a late response may correspond to an earlier send.

* Current baseline timeout policies:

  | Policy | ARP | ICMP | TCP SYN |
  |---|---:|---:|---:|
  | Initial manager timeout | 1.25 s | 1.5 s | 7 s |
  | Manager minimum | 350 ms | 500 ms | 750 ms |
  | Manager maximum | 5 s | 8 s | 12 s |
  | Additional scanner minimum | — | — | 3 s initially |
  | Retries | 2 | 3 | 1 |

* TCP SYN retains a conservative initial minimum even after observing fast closed-port RST replies. This avoids aggressively classifying slower SYN/ACK responses as filtered.

## ICMP Discovery

* Retained the shared, event-driven ICMP scanner, the **500 outstanding-probe window**, the identifier/sequence/IP reply matching, and the **three retries** introduced in v1.0.3.

* Replaced the prior fixed per-attempt timeout with adaptive deadlines and exponential retry backoff.

* Added a shared transmit schedule capped at **50 ICMP packets/second** instead of bursting hundreds of pending probes simultaneously.

* Added temporary backoff for local send congestion (`ENOBUFS` / `EAGAIN`), including a **150 ms pause** and a limit on consecutive failures.

* A transmission rejected by the kernel no longer consumes a successful network retry or silently skips the destination; sustained failures are reported rather than misclassified as host nonresponse.

* Final `TimedOut` accounting now occurs only when all permitted transmissions have been exhausted.

* Added handling for late responses after a retry, duplicate response suppression, and omission of ambiguous post-retry RTT samples.

* ICMP nonresponse remains reachability evidence only; it does not exclude a target from TCP SYN scanning.

## TCP SYN Scanning

* Retained the half-open SYN/RST discovery model introduced in v1.0.3; full TCP connections remain limited to enrichment of open ports.

* Moved the TCP implementation into dedicated subpackages:

  ```text
  internal/portscan/tcp/
    probe/    Raw packets, TCP checksums, source selection, send/receive
    search/   Port jobs, pending probes, retries, state classification
    enrich/   Banners, fingerprinting, and service resolution
  ```

* Increased the outstanding SYN probe window from **500** (v1.0.3) to **2,048**.

* Added a paced sender supporting up to **500 transmissions/second**, including retransmissions, rather than dispatching the entire outstanding window in one burst.

* Replaced the fixed 10-second per-probe deadline used during development with adaptive TCP deadlines, a conservative **3-second initial floor**, and **one SYN retry**.

* Added per-probe retry count, transmit time, and deadline tracking. A port becomes `filtered` only when the permitted SYN transmissions have completed without a matching answer by the final deadline.

* Added congestion recovery for temporary `ENOBUFS`/`EAGAIN` send failures. The port cursor and retry allowance no longer advance for a rejected transmission.

* Increased the raw reply channel buffer to **8,192** entries and replaced silent channel-overflow discards with receiver backpressure and coordinated shutdown.

* Kept response matching by remote IP/port, local source port, and valid TCP acknowledgement checks for SYN/ACK and RST/ACK responses.

* Retained SYN/ACK → `open`, RST → `closed`, and exhausted/no-response → `filtered` classification.

* Kept cleanup RST transmissions separate from SYN discovery statistics.

* Preserved memory-conscious results for multi-target full-range scans: count closed/filtered ports without storing every port number unless explicit selection requires detailed results.

## Service Identification and Fingerprinting

* Expanded enrichment from v1.0.3's basic service/banner/HTTP inspection into an **evidence-based identification workflow**:

  ```text
  Open TCP port
       ↓
  Embedded IANA registry lookup
       +
  Passive / active fingerprinting
       ↓
  Compare evidence and aliases
       ↓
  Resolved service + reason
  ```

* Added an embedded **IANA Service Name and Transport Protocol Port Number Registry** for registered names, instead of treating common port-to-service associations as proof of the running protocol.

* Separated `DBLookup` (registered service), `Fingerprint` (observed behavior), and `Service` (resolved selection). The original evidence remains available when the two disagree.

* Added service aliases for equivalent names (for example, IANA `domain` and detected `dns`) while preserving distinctions such as HTTP versus HTTPS.

* Added fingerprint confidence levels, supporting evidence, service-resolution reasons, and the ability to retain multiple recognized protocol observations for one port.

* Expanded fingerprinting methods to include:

  * SSH identification banners;
  * recognizable FTP and SMTP greetings;
  * plaintext HTTP responses;
  * HTTPS responses over TLS;
  * validated DNS-over-TCP responses;
  * generic TCP banner and request/response inspection.

* Integrated **Rapid7 Recog** signature matching into supported fingerprint analysis, allowing products and supporting signature evidence to be reported where identified.

* HTTP fingerprinting now preserves response status, selected headers, and server/product hints. Sensitive fields including `Set-Cookie`, `WWW-Authenticate`, and `Proxy-Authenticate` are redacted in output.

* DNS-over-TCP fingerprinting now checks length framing, transaction ID, DNS response flags, question count, and expected question content before confirming the protocol.

* Fingerprints can override conflicting IANA names when sufficiently supported; unknown or unrecognized protocols remain `unknown` rather than being claimed as verified from port registration alone.

* Kept TCP connection latency separate from the SYN RTT and from the full fingerprinting duration.

* As of v3.0.0, Telnet negotiation bytes can be captured as evidence but are not necessarily recognized as a confirmed Telnet fingerprint.

## Network Performance

* Added a shared per-protocol performance subsystem:

  ```text
  internal/network/app/
  ```

* Added separate statistics for **ICMP, ARP, TCP SYN, DNS, NetBIOS, TCP Connect, HTTP, HTTPS, and DNS-TCP**.

* Added counters and timing information:

  * `Sent` — transmissions/operations started, including successful retransmissions;
  * `Retries` — retransmissions of existing logical requests;
  * `Received` — classifying replies or successful operations;
  * `TimedOut` — final exhausted timeouts;
  * `Dropped` — non-timeout errors or unusable responses;
  * RTT minimum, average, and maximum;
  * average transmission/operation rate.

* Established explicit send/retry accounting: a successful retransmission increments both `Sent` and `Retries`, without creating a new logical request.

* Replaced the old `TimeoutOnError()` helper with `app.Fail(protocol, err)`, which records timeouts as `TimedOut` and other non-nil failures as `Dropped`.

* Updated TCP Connect, HTTP/HTTPS, DNS-TCP, and NetBIOS enrichment paths to classify failed writes, reads, malformed replies, and other operation errors rather than leaving attempts unclassified.

* TCP connection establishment and later application-level requests are recorded separately. For TLS-enabled probes, the TCP Connect outcome currently includes the TLS handshake.

## Network Diagnostics

* Replaced the misleading percentage-based **Network Health** rating with **Network Diagnostics**.

* A low number of responding addresses on a largely unused subnet no longer causes the scanner to label the network `Degraded`.

* Diagnostics now distinguish response rate from accounting completeness:

  ```text
  Requests      = Sent - Retries
  Classified    = Received + TimedOut + Dropped
  Unclassified  = Requests - Classified
  ResponseRate  = Received / Requests × 100
  Coverage      = Classified / Requests × 100
  ```

* Added meaningful accounting states:

  * `Complete` — every recorded logical request has a final outcome;
  * `Partial` — one or more requests have no classified outcome;
  * `Inconsistent` — impossible or contradictory counters;
  * `No data` — no requests recorded.

* Removed the misleading overall network-health score. **100% coverage means complete outcome accounting**, not that every device responded or that network quality is perfect.

## Output, Reporting, and Timing

* Expanded terminal output into independent ICMP, ARP, TCP SYN, Service Identification, and Scan Results stages, according to the selected engines.

* Added dedicated **Execution Times**, **Network Performance**, and **Network Diagnostics** summaries after a scan.

* Added structured ARP device tables with manufacturer, PTR/NetBIOS, MAC, and interface data.

* Added separate **DB Lookup** and **Fingerprint Lookup** tables, followed by resolved services, per-port evidence, banners, and supported HTTP headers.

* Preserved sensitive-header redaction in terminal output and Markdown reports.

* Retained Markdown report export with `-s`, now capable of reflecting the expanded discovery and service-identification evidence.

* Preserved target and port specifications in reports; the selected execution stages determine which information is available.

  ```text
  internal/
    network/
      timeout/            RTT estimation and retry backoff
      app/                Per-protocol statistics and diagnostics
    portscan/
  ```

* Added locally embedded data sources for IEEE MAC registration and IANA TCP service names. These can be refreshed from upstream data, with a rebuild required before an updated embedded dataset appears in the binary.

* Split fingerprinting, probe sending, capture, analysis, signature recognition, and service resolution into focused packages.

## Current Scan Flow

```text
Target flag or interactive IPv4/CIDR input
                ↓
Select ICMP / ARP / TCP engines
                ↓
       ICMP discovery
                ↓
       ARP discovery + enrichment
                ↓
    Discovery-based target prioritization
                ↓
        TCP SYN scanning
                ↓
       Open TCP ports only
                ↓
       IANA registry lookup
                +
       Evidence-based fingerprinting
                ↓
       Final service resolution
                ↓
       Terminal output / Markdown export
                ↓
    Execution times + performance + diagnostics
```

Each stage executes only if its corresponding engine or dependent work is enabled. The principal changes since v1.0.3 are the new ARP/device-identification engine, modular service fingerprinting, and the shared adaptive timeout, retry, performance, and diagnostics infrastructure.

## Limitations

* TCP SYN scanning currently targets IPv4 and requires appropriate raw-socket privileges.
* ARP discovery is local to eligible Layer 2 networks; normal routers do not forward ARP broadcasts.
* ICMP silence or a TCP timeout does not prove that a host or port is permanently unreachable. Firewalls, routing, congestion, or packet loss may affect classification.
* Vendor assignments, PTR records, and NetBIOS names are observational evidence, not authenticated device identities.
* HTTPS fingerprinting disables TLS certificate verification for identification and does not authenticate a remote server.
* Binary Telnet negotiation is not yet guaranteed to receive a confirmed Telnet fingerprint.
* Some application protocol variants remain unsupported and may resolve to `unknown`.
* Fully filtered full-range or large-CIDR scans can consume significant time and generate substantial traffic.

Only scan systems and networks you own or are explicitly authorized to assess.
